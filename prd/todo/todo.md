## 2. 技术决策

| 层级 | 选型 | 理由 / 说明 |
| --- | --- | --- |
| 桌面框架 | Tauri 2 | 体积小、内存占用低，Rust 后端直接调用 Windows API |
| 后端语言 | Rust | 系统 API 调用、进程操作 |
| 端口表 | `windows` crate | 调用 `GetExtendedTcpTable` / `GetExtendedUdpTable`，核心能力自行实现 |
| 进程信息 | `sysinfo` crate | 进程名、EXE 路径、命令行、工作目录、父 PID、启动时间、CPU、内存，减少自行读取 PEB 的代码 |
| 错误处理 | `thiserror` + `serde` | Rust 错误枚举统一序列化为 `{ code, message }` 返回前端 |
| 类型同步 | `ts-rs`（或 `tauri-specta`） | 由 Rust 结构自动生成 TS 类型，避免手工维护 |
| 前端 | React 19 + TypeScript + Vite | — |
| 样式 | Tailwind CSS 4（`@tailwindcss/vite`） | — |
| 组件 | shadcn/ui + Lucide Icons | — |
| 设置存储 | `tauri-plugin-store` | 主题、最近查询的常用端口、关闭等待时长等少量配置，MVP 即可使用 |
| 数据库 | SQLite（P2 引入） | MVP 不引入，以实时系统信息为主；P2 做历史记录/收藏/操作审计日志时使用 Rust 侧 `rusqlite`，通过类型化 Command 暴露，**不使用 `tauri-plugin-sql`**（会向前端暴露任意 SQL 执行能力） |

- [ ] 初始化 Tauri 2 + React 19 + TS + Vite 项目
- [ ] 接入 Tailwind CSS 4 与 shadcn/ui
- [ ] 接入 Rust 依赖：`windows`、`sysinfo`、`thiserror`、`serde`、`ts-rs`
- [ ] 最小化 Tauri capabilities，不启用 shell 等无关插件

### 5.1 应用识别

- [ ] 优先根据命令行参数和路径判断应用，而不是只看进程名
- [ ] `node.exe` 尝试识别为 Node.js / Vite / Next.js 等具体用途
- [ ] `java.exe` 尝试识别 Spring Boot / IntelliJ 相关开发进程
- [ ] `python.exe` 尝试识别 FastAPI / Flask / Django 等用途
- [ ] `mysqld.exe` 识别 MySQL
- [ ] `redis-server.exe` 识别 Redis

### 5.2 特殊占用者识别

- [ ] PID `0`（如 `TIME_WAIT` 记录）：标记为不可操作，说明连接正在等待系统回收
- [ ] PID `4`（System）占用 80/443 等端口：识别为 HTTP.sys / IIS，不可结束，提示使用 `netsh http show servicestate` 排查
- [ ] `svchost.exe`：显示其托管的 Windows 服务名，建议停止服务而不是结束进程
- [ ] Docker Desktop（`com.docker.backend.exe` 等）：识别为容器端口映射，提示使用 `docker stop`，不建议直接结束
- [ ] WSL（`wslrelay.exe` 等）：识别为 WSL 端口转发，提示在 WSL 内处理

## 6. MVP：进程操作

### 6.1 正常关闭

> Windows 没有 SIGTERM。node / java / python 等开发服务器多为无窗口的控制台进程，发送 `WM_CLOSE` 或不带 `/F` 的 `taskkill` 会失败，因此需要降级策略。

- [ ] 提供“关闭进程”按钮
- [ ] 操作前显示确认弹窗
- [ ] 操作前校验 PID + 启动时间与查询时一致，不一致则中止并提示重新查询
- [ ] GUI 进程：向顶层窗口发送 `WM_CLOSE`
- [ ] 控制台进程：`AttachConsole` 后发送 `CTRL_C_EVENT` / `CTRL_BREAK_EVENT`（注意屏蔽自身的控制台信号处理）
- [ ] 等待进程退出，默认超时 5 秒（后续可在设置中调整）
- [ ] 等待期间显示倒计时，并提供“立即强制结束”按钮
- [ ] 超时或失败后提示“是否强制结束”
- [ ] 操作成功后重新查询端口
- [ ] 操作失败显示原因
- [ ] 处理权限不足情况

### 6.2 强制结束

- [ ] 提供“强制结束”按钮
- [ ] 显示高风险确认提示
- [ ] 操作前校验 PID + 启动时间
- [ ] 执行强制结束（`TerminateProcess`）
- [ ] 操作完成后重新查询端口
- [ ] 处理权限不足情况

### 6.3 进程树

### 6.4 安全保护

- [ ] 识别 Windows 系统关键进程
